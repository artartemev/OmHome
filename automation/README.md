# Автоматизация афиш OmHome

Короткое сообщение с расписанием превращается в афиши в фирменном стиле, блок «Афиша» на сайте и посты в Telegram.

```
расписание (текст) ──► announcement.mjs ──► события (дата, время, название, описание)
                                         ├─► poster/render.mjs ──► public/posters/<id>.jpg и <id>-story.jpg
                                         ├─► public/events.json ──► блок «Афиша» на omhome.space
                                         └─► formatPost() ──► пост в @omhome_thai + пересылка в дружественные чаты
```

## Свободный текст

Можно писать как удобно: «в четверг в шесть Даша проводит мантра-йогу, в инсте она au_darya, в субботу как обычно киртан, в воскресенье в пять Шляпа, запись у @Wasyaphi». Если текст не в строгом формате ниже (или указан `--ai-parse`), Gemini сначала переписывает его в этот формат — результат печатается («🧠 Gemini разобрал анонс так»), — а дальше всё как обычно, с превью и ✅. Если у события нет описания, подставляется стандартное из `automation/defaults.json` (сейчас — для киртана).

## Формат сообщения

Одно или несколько событий, между ними пустая строка:

```
сб 17/10 18:00
Киртан
Поём мантры вместе, чай после

18.10 17:00
Шляпа | настольная игра

20 октября 11:00 и 18:00
Чайная | медитация и дегустация
```

- Первая строка: дата (`17/10`, `17.10`, `17 октября`), день недели (необязательно) и время. Если день недели не совпадает с датой, скрипт предупредит.
- Вторая строка: название. Через `|` можно добавить подзаголовок: на афише он встаёт маленькой строкой над названием.
- Пометки для Instagram — строкой `инста: @ник` или фразой «в инсте она ник» внутри описания: в Telegram и на сайт они не попадают, а в посте Instagram аккаунт отмечается (`@ник`). Telegram-ники (`@...`) в Instagram превращаются в `t.me/...`, чтобы не отмечать случайных людей.
- `✍️ Запись: @ник` — если записываться не к @artartemev.
- Остальные строки: описание. Подвал анонса (📍 адрес, ✍️ запись, 💰 донейшен) добавляется сам. Ссылку на реквизиты omhome.space/donate в подвал можно вернуть флагом `donateLink` в `announcement.mjs`.

## Запуск

```bash
# пробный прогон: афиши + events.json + текст постов в консоль
npm run publish:events -- schedule.txt --photo "Киртан=./kirtan.jpg" --photo "Шляпа=./hat.jpg"

# одна афиша вручную
node automation/poster/render.mjs --date 2026-10-17 --time 18:00 --title "Киртан" --photo ./kirtan.jpg --palette teal --out public/posters/2026-10-17-kirtan

# публикация: каждое действие ждёт вашего ✅
npm run publish:events -- schedule.txt --photo "*=./photo.jpg" --send
```

## Подтверждение каждого действия

С `--send` ничего не уходит без вашего одобрения. Каждое действие — отдельный вопрос:

1. 📣 пост в канал @omhome_thai;
2. 🔁 репост в каждый чат из `TELEGRAM_REPOST_CHAT_IDS` (формат `id=Название`, например `-1001234=Волшебный чат`);
3. 📸 пост в Instagram (если задан `IG_ACCESS_TOKEN`); после публикации бот присылает ссылку на пост и напоминает поделиться им в историю — сториз вручную из приложения;
4. 🔁 репост в чаты, куда бота добавить нельзя (Волшебный чат), — с вашего аккаунта через Telethon: `TG_USER_REPOST_CHATS="https://t.me/+…=Волшебный чат"`;
5. 💌 личное сообщение партнёрам (Вероника) — одно на всю неделю: в превью видно точное приветствие и список афиш.

Если задан `TELEGRAM_APPROVAL_CHAT_ID` (ваш чат с ботом @OmHome_Sch_bot — напишите ему /start), превью с картинкой и текстом приходит туда с кнопками «✅ Опубликовать» / «❌ Пропустить» — одобрять можно с телефона. Иначе скрипт спрашивает в терминале `[y/N]`. Нет ответа (6 часов) или нет ни чата, ни терминала — значит «нет». Если пост в канал пропущен, а репост одобрен, в чат уходит сама афиша вместо пересылки.

Сайт обновляется отдельно: `public/events.json` меняется локально и попадает на omhome.space только после вашего коммита.

`--photo "*=path"` задаёт одно фото для всех событий. Фото без названия (`--photo a.jpg --photo b.jpg`) раскладываются **по порядку событий в тексте**: первое — к первому событию и т. д. События похожи, поэтому угадывать по картинке ненадёжно; `--photo-match ai` даёт выбрать Gemini. Итоговые афиши в любом случае приходят на ✅. Приложенное фото просто встаёт в арку — ничего не ищется и не генерируется. `--poster "Название=path"` берёт готовую афишу (например, из Figma) как есть.

**Ротация фото.** Если к киртану не приложено фото, берётся следующее из `automation/photos/kirtan/` — то, что использовалось давнее всех (история в `automation/photos/history.json`), так что подряд одно и то же не повторяется. Новые фото просто кладите в эту папку; для других регулярных форматов можно завести папку с названием категории (`cinema`, `games`, `practice`, `tea`, `talks`).

Цвет афиши закреплён за типом события (цвета взяты из афиш в Figma): киртан — `teal`, кино — `ocean`, игры — `navy`, практики — `sea`, чай — `olive`, беседы — `brown`. `--palette` переопределяет.


### Правки на ❌

На «❌ Нет / поправить» бот спрашивает «✏️ Что поправить в анонсе?». Ответьте на это сообщение (реплаем) текстом — «время 19:30», «подзаголовок — с Сашей», «сократи описание» — и/или фото, которое поставить в афишу. Gemini вносит правку, афиша, пост и запись на сайте пересобираются, превью приходит заново. «🗑 Отменить анонс» убирает событие везде (и с сайта), «⏭ Только пропустить» — пропускает только это действие. Править можно, пока событие ещё никуда не опубликовано; в терминале правка пишется прямо в ответ на вопрос, `c` — отменить анонс, `фото: путь` — заменить фото.

### Бот-приёмник анонсов

```bash
node --env-file=.env automation/bot.mjs
```

Пишете боту @OmHome_Sch_bot анонс (строгий формат или свободный текст, можно альбомом с фото — подпись это анонс) → он запускает `publish.mjs --send --site` и присылает превью на ✅/❌. Флаги можно поменять через `PUBLISH_ARGS`. Бот слушает, пока процесс запущен: на Mac — пока открыт терминал (или через launchd/pm2).

## Нейросети

```bash
# текст: polish — поправить, expand — расширить, shorten — сократить (Gemini 3.8 Flash, запасные 3.5 Flash / Flash Latest)
npm run publish:events -- schedule.txt --ai-text expand --photo "*=./photo.jpg"

# фото: если для события не передано --photo, оно генерируется
npm run publish:events -- schedule.txt --ai-photo
```

- Ключи кладутся в `.env` в корне (файл в `.gitignore`): `GEMINI_API_KEY=...`, при желании `CLOUDFLARE_ACCOUNT_ID=...` и `CLOUDFLARE_API_TOKEN=...`. Перед запуском: `set -a; . ./.env; set +a`.
- Фото рисует Cloudflare Workers AI (FLUX.1 schnell; Gemini сначала пишет для него конкретную сцену по-английски — предметы события, без текста и алкоголя; стиль — `IMAGE_STYLE=photo` по умолчанию, `illustration` пока выходит слабо; бесплатно 10 000 «нейронов» в сутки — хватает с запасом на 5–7 картинок в неделю). Запасной вариант — Gemini (Nano Banana), но на бесплатном тарифе AI Studio у него квота 0, нужен биллинг.
- Cloudflare: зарегистрируйтесь на dash.cloudflare.com → Workers AI → «Use REST API»: там Account ID и кнопка создания API-токена с правом Workers AI.

## Репост партнёрам

Бот не может написать человеку первым, поэтому партнёрам (@VeronikaKirpichenko) афиша уходит с вашего аккаунта через Telethon — той же сессией, что в проекте guide. С `--send` (и после вашего ✅) это происходит, если заданы `TG_API_ID`, `TG_API_HASH`, `TG_SESSION` (путь к .session). Первым сообщением уходит короткое «привет, вот анонс, буду благодарен за репост» — каждый раз в другой формулировке (варианты в `INTROS` в `telegram_user.py`, подряд один и тот же не повторяется), вторым — афиша с текстом. Список партнёров: `TG_PARTNERS=VeronikaKirpichenko,другой_ник`.

## Instagram

Публикация через официальный Instagram API с входом через Instagram (`automation/instagram.mjs`, `graph.instagram.com`): нужен профессиональный аккаунт, приложение Meta и токен пользователя Instagram (`IG…`) с `instagram_business_content_publish` — `IG_ACCESS_TOKEN` в `.env` (`IG_USER_ID` необязателен). Проверить токен, ничего не публикуя: `node automation/instagram_check.mjs`. Instagram сам скачивает картинку по ссылке, поэтому афиши должны быть уже задеплоены на omhome.space (`IG_PUBLIC_BASE_URL`). На живом аккаунте ещё не проверялось — первый запуск лучше провести вместе.

## Бот на сервере (Railway)

`automation/server/` — образ с Chromium, git и Telethon. Код в образ не зашит: при старте репозиторий клонируется из GitHub, а перед каждым анонсом подтягивается свежий `main`, поэтому правки кода доходят до бота без передеплоя.

```bash
cd automation/server && railway up        # сборка и запуск
```

Переменные сервиса: всё из `.env` (GEMINI_API_KEY, TELEGRAM_*, TG_USER_REPOST_CHATS, IG_*, CLOUDFLARE_*), плюс
- `GITHUB_TOKEN` — fine-grained токен только на artartemev/OmHome с правом Contents: Read and write (для обновления афиши на сайте);
- `TG_API_ID`, `TG_API_HASH`, `TG_SESSION_STRING` — для Волшебного чата и Вероники; строку даёт `python3 automation/server/make_session.py` (отдельная сессия «OmHome bot server», а не сессия guide).

Бот должен работать в одном месте: два процесса с одним токеном мешают друг другу получать сообщения.

## Отзывы Google на сайте

Тем же способом, что в guide (`gmaps_reviews.py`): Chrome открывает карточку OmHome Space на Google Maps и читает рейтинг и отзывы как человек, без API. Из облака (и с сервера) Google показывает урезанный вид без текстов, поэтому запускать на Mac — там подхватится профиль Chrome от guide (`~/.chiangmai_guide_chrome`):

```bash
cd OmHome && git pull && npm install && npm run reviews   # собрать → закоммитить public/reviews.json → push в main
```

Раз в неделю-две достаточно. Если Google всё же покажет урезанный вид, собранные ранее отзывы на сайте не стираются. Скрыть отзыв или подставить полный текст (Google обрезает длинные на «…») — в `automation/reviews/overrides.json`.

## Волшебный чат и партнёры: анонс недели

Анонсы приходят по одному в течение недели и уходят в канал, на сайт и в Instagram. А дружественные чаты (`TG_USER_REPOST_CHATS`) и партнёры (`TG_PARTNERS`, по умолчанию @VeronikaKirpichenko) раз в неделю получают **одно сообщение — один общий текст**: тёплое вступление от первого лица и живой абзац про одно событие недели (субботний киртан, `WEEKLY_FEATURE`) с его афишей, а ниже — «Ещё на неделе:» — остальные события ближайших 7 дней списком, каждое со ссылкой на свой пост в канале. Ссылку на пост бот запоминает при публикации в канал (поле `post` в `public/events.json`), для старых событий находит её в ленте канала по дате и названию. Партнёру перед сообщением уходит приветствие («Привет) вот анонс на грядущую неделю…»).

```bash
node automation/weekly.mjs            # вручную; бот запускает сам по расписанию и по команде /week
```

Бот собирает анонс по `WEEKLY_AT` (по умолчанию `mon 11:00`, время Чиангмая) и присылает превью на ✅/❌; на ❌ — реплай правкой («короче», «больше про киртан») или «заново». Если в афише на неделю пусто — бот напомнит прислать анонсы.

Отправка — с вашего аккаунта (Telethon: `TG_SESSION` / `TG_SESSION_STRING`). Пока сессии нет, после ✅ бот присылает готовую афишу с текстом вам — переслать вручную.
